# gift-rental-bot · Аренда NFT-подарков Telegram

Telegram Mini App + бот, всё живёт в одном GitHub-репозитории:

- **Мини-апп** — GitHub Pages, статика, 24/7.
- **Бот** — GitHub Actions (keep-alive: cron каждые 5 минут, guard от дублей, job до ~350 минут). Аптайм ~98%, паузы рестартов до ~10 минут — предел платформы.
- **Реальные подарки** — бот через Bot API `getUserGifts` читает unique-подарки каждого пользователя и коммитит `data/gifts/<uid>.json` + стикеры в `assets/gifts/` каждые 10 минут. Фронт рендерит их как в Telegram: модель, символ, фон, номер `#N`.
- **Верификация** — пользователь собирает витрину, жмёт «Верифицировать», вставляет пейлоад боту. Бот сверяет подарки с реальным профилем и подписывает витрину (ECDSA P-256, приватный ключ в GitHub Secrets). Подпись проверяется в браузере, подмена ломает значок.
- **Контроль** — жалоба кнопкой из витрины (`/start rp_...`), стоп-лист `denylist.json`, команды `/block`, `/complaints`.

## Файлы

```
index.html, app.js, style.css   мини-апп (Pages, корень репозитория)
bot/main.py                     бот: поллинг, getUserGifts, подпись, жалобы, блок
bot/repo.py                     батч-коммиты в репозиторий (git data API)
bot/signing.py                  ECDSA подпись в формате WebCrypto (P-1363)
data/users.json                 зарегистрированные пользователи
data/gifts/<uid>.json           реальные подарки пользователей
assets/gifts/*.webp             стикеры подарков
denylist.json                   стоп-лист
.github/workflows/bot.yml       keep-alive раннер
.github/workflows/pages.yml      публикация Pages
```

## Секреты (Settings → Secrets → Actions)

- `TELEGRAM_BOT_TOKEN` — токен из BotFather.
- `SIGNING_KEY` — PEM приватного ключа подписи (публичный зашит в `app.js`, CONFIG.verifyKey).
- `ADMIN_IDS` — Telegram ID админа (свой id можно спросить у бота: `/myid`), через запятую.

## Запуск

1. Всё уже должно быть запушено; проверить Secrets выше.
2. BotFather: `/newapp` → выбрать `@free_rental_bot` → название → short name `gifts`
   → URL `https://<логин>.github.io/gift-rental-bot/` → Web App.
   (или свой short name — тогда поменять `CONFIG.appShortName` в `app.js` и переменную репо `APP_SHORT_NAME`)
3. Settings → Pages → Build and deployment: **GitHub Actions** (workflow `pages.yml` уже в репо).
4. Ждать первого запуска workflow `bot` (крон раз в 5 минут или Run workflow руками).
5. Проверка цепочки: `/start` боту → открыть мини-апп → выставить цены → «Верифицировать» → вставить пейлоад боту → получить подписанную ссылку → открыть её.

## Как работает верификация

1. Мини-апп собирает витрину из **реальных** подарков (`data/gifts/<uid>.json`, источник `getUserGifts`).
2. Бот при `/verify` (или просто вставленному пейлоаду) заново вызывает `getUserGifts` для отправителя и сверяет каждый подарок витрины с профилем. Подделка невозможна: несуществующий подарок не пройдёт сверку.
3. Бот подписывает пейлоад и возвращает ссылку с кнопкой «Скопировать».
4. Клиент, открыв витрину, видит зелёный значок. Если содержимое изменили после подписи — красный.

## Ограничения (честно)

- Бот в Actions — ~98% аптайма; при рестарте пауза до ~10 минут.
- Подарки читаются только если они видны в профиле (Telegram ограничение).
- Витрина — это ссылка: пейлоад ≤ ~4 КБ (≈20-25 подарков).
- `getUserGifts` работает для пользователей, взаимодействовавших с ботом (мини-апп открывается через бота — условие выполнено).
